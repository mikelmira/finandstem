# Fin & Stem — Sitemap Plan

Sitemap is generated by `app/sitemap.ts` at build time. Re-runs on every ISR revalidation so newly-added catalogue entries appear within the revalidate window.

## Sitemap structure

```
/sitemap.xml              ← Sitemap index, references all sitemaps below
/sitemap-core.xml         ← Homepage, about, contact, legal, compatibility tool
/sitemap-pillars.xml      ← 6 pillar pages
/sitemap-plants.xml       ← Every /plants/[slug] page
/sitemap-fish.xml         ← Every /fish/[slug] page
/sitemap-shrimp.xml       ← Every /shrimp/[slug] page
/sitemap-mosses.xml       ← Every /mosses/[slug] page
/sitemap-hardscape.xml    ← Every /hardscape/[slug] page (when collection launches)
/sitemap-equipment.xml    ← Every /equipment/[slug] page (when collection launches)
/sitemap-builds.xml       ← Every /builds/[slug] page
/sitemap-guides.xml       ← Every /guides/[slug] page
```

Splitting by content type makes incremental updates obvious in Google Search Console — when "guides" sitemap grows from 10 to 20 entries, you see it.

## Per-entry fields

Each `<url>` element includes:

```xml
<url>
  <loc>https://finandstem.com/fish/neon-tetra</loc>
  <lastmod>2026-08-12T14:30:00+00:00</lastmod>
  <changefreq>monthly</changefreq>
  <priority>0.8</priority>
</url>
```

| Field | Source | Notes |
|---|---|---|
| `loc` | Payload `slug` field | Always HTTPS, no trailing slash |
| `lastmod` | Payload `updatedAt` | ISO 8601 with timezone |
| `changefreq` | Hardcoded per page type | See table below |
| `priority` | Hardcoded per page type | See table below |

## Priority and changefreq by page type

| Page type | changefreq | priority |
|---|---|---|
| Homepage | daily | 1.0 |
| Pillar pages | weekly | 0.9 |
| Catalogue entries (species) | monthly | 0.8 |
| Build journals | monthly | 0.7 |
| Guides | monthly | 0.7 |
| Compatibility tool | weekly | 0.9 |
| Category landing pages (`/plants`, `/fish`) | weekly | 0.8 |
| About / author | yearly | 0.6 |
| Filter URLs (e.g. `/plants?light=low`) | — | **excluded** (canonical to base) |

## What's NOT in the sitemap

- Filter URLs (canonical to base, don't dilute crawl budget).
- `/admin/*` and `/api/*` routes.
- 404 page.
- Search results pages (no permanent content).
- Draft / unpublished collection items.

## Submission

After deploy:
1. Verify ownership in [Google Search Console](https://search.google.com/search-console).
2. Submit `https://finandstem.com/sitemap.xml`.
3. Verify in [Bing Webmaster Tools](https://www.bing.com/webmasters/).
4. Submit the same URL.
5. Cloudflare Pages automatically serves the sitemap with proper Cache-Control headers — no further config needed.

## Implementation notes for Claude Code

```typescript
// app/sitemap.ts
import { getPayload } from 'payload';
import config from '@payload-config';

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const payload = await getPayload({ config });

  const [plants, fish, shrimp, mosses, builds, guides] = await Promise.all([
    payload.find({ collection: 'plants', limit: 1000 }),
    payload.find({ collection: 'fish', limit: 1000 }),
    payload.find({ collection: 'shrimp', limit: 1000 }),
    payload.find({ collection: 'mosses', limit: 1000 }),
    payload.find({ collection: 'builds', limit: 1000 }),
    payload.find({ collection: 'guides', limit: 1000 }),
  ]);

  const BASE = 'https://finandstem.com';
  const staticPages: MetadataRoute.Sitemap = [
    { url: `${BASE}/`, lastModified: new Date(), changeFrequency: 'daily', priority: 1.0 },
    { url: `${BASE}/about`, lastModified: new Date(), changeFrequency: 'yearly', priority: 0.6 },
    { url: `${BASE}/compatibility`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/plants`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.8 },
    { url: `${BASE}/fish`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.8 },
    { url: `${BASE}/shrimp`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.8 },
    { url: `${BASE}/mosses`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.8 },
    { url: `${BASE}/builds`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.7 },
    { url: `${BASE}/guides`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.7 },
    // Pillar pages
    { url: `${BASE}/planted-tank-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/aquarium-fish-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/freshwater-shrimp-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/aquatic-moss-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/aquarium-hardscape-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
    { url: `${BASE}/aquarium-equipment-guide`, lastModified: new Date(), changeFrequency: 'weekly', priority: 0.9 },
  ];

  const speciesEntries = [
    ...plants.docs.map(p => ({ url: `${BASE}/plants/${p.slug}`, lastModified: p.updatedAt, changeFrequency: 'monthly' as const, priority: 0.8 })),
    ...fish.docs.map(p => ({ url: `${BASE}/fish/${p.slug}`, lastModified: p.updatedAt, changeFrequency: 'monthly' as const, priority: 0.8 })),
    ...shrimp.docs.map(p => ({ url: `${BASE}/shrimp/${p.slug}`, lastModified: p.updatedAt, changeFrequency: 'monthly' as const, priority: 0.8 })),
    ...mosses.docs.map(p => ({ url: `${BASE}/mosses/${p.slug}`, lastModified: p.updatedAt, changeFrequency: 'monthly' as const, priority: 0.8 })),
  ];

  const buildEntries = builds.docs.map(b => ({
    url: `${BASE}/builds/${b.slug}`,
    lastModified: b.updatedAt,
    changeFrequency: 'monthly' as const,
    priority: 0.7,
  }));

  const guideEntries = guides.docs.map(g => ({
    url: `${BASE}/guides/${g.slug}`,
    lastModified: g.updatedAt,
    changeFrequency: 'monthly' as const,
    priority: 0.7,
  }));

  return [...staticPages, ...speciesEntries, ...buildEntries, ...guideEntries];
}
```

(If we exceed 50,000 URLs we'll switch to a manual sitemap-index file with per-collection sitemaps. We won't hit this in year 1.)
